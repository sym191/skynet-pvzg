# 阶段八：稳定性、性能与发布验收

状态：待实施。基线与通用约束见 [规划索引](README.md)。

## 目标与进入条件

对拟发布范围给出可复现的兼容性、内存/并发安全、长稳和性能证据，交付配置迁移、运行、
限制及回滚文档。阶段六、七每次开发即补充测试，阶段八集中封闭缺口和发布门槛。
本计划没有产生新的运行结果或性能数据。

进入正式验收前冻结候选提交、上游提交、工具链、Lua/依赖版本、支持矩阵及测试配置。
必选能力未完成时先回到对应阶段修复；不通过减少测试范围宣称完整验收。
性能优化必须基于测量单独提交，优化后重新执行受影响门禁。

## 8A：兼容性与业务回归

同一 Lua workload 分别运行 original/refactor；分布式另跑 R→R、O→R、R→O，
以 O→O 建立原版基准。输出结构化记录，包含操作、逻辑服务/节点、关联 ID、返回值、错误及事件。
归一化动态 handle、socket ID、墙钟和日志装饰；保留协议、二进制内容、source/session 关系、
契约保证的顺序及失败结果。无顺序保证的跨服务交错按因果关系或集合比较。

| 门禁 | 必测内容 |
| --- | --- |
| 配置/启动 | 默认值、include/环境变量、非法类型、bootstrap/launcher、启动失败退出 |
| 消息/调度 | 协议号、空/NUL/大消息、copy/adopt/forward、失败投递、唯一 ID 集合、单服务串行、每 producer FIFO |
| 生命周期/时间 | init/EXIT/KILL/stop 竞争、服务重复创建、session/handle 边界、timer 顺序与取消、CPU 时间统计 |
| Lua/C ABI | loader、coroutine、call/response、序列化交叉解码、OOM、native 模块失败卸载 |
| 网络 | TCP 半包/粘包/慢读、IPv4 UDP 空包/最大包、FD 保留语义、owner 转移、关闭与在途写、统计 |
| 分布式 | 阶段六两套矩阵、全局名称与节点配置、分片、断线与 pending 请求、恢复与停机 |
| 扩展/运维 | 阶段七矩阵、跨 VM/GC、allocator 归属、PID/信号/日志/调试生命周期 |
| 业务 | 登录重复/并发/失败、玩家服务退出与重建、组队模型、RPC seed/recover/rollback、状态文件锁及重启恢复 |

业务用例使用临时独立状态文件，保留“持久化成功后发布”的既有约束。
阶段六测试不会让多个节点共同写现有组队 JSON 文件，也不宣称登录已支持跨节点唯一性。
UDP IPv6、普通文件 FD、自定义 socket buffer 等延期/未支持项在覆盖报告中显式列出。

## 8B：构建与 sanitizer

当前可用的普通构建/测试入口如下，未来新增用例须注册到实际 CTest 清单中：

```bash
cmake --preset linux-debug
cmake --build --preset all-debug -j 4
ctest --preset linux-debug --output-on-failure
cmake --preset linux-release
cmake --build --preset all-release -j 4
ctest --preset linux-release --output-on-failure
```

另执行 [Lua 说明](../../lua/README.md) 中的模型、业务 RPC 和启动器验证，不能假定所有业务测试都已纳入 CTest。
基线的 21 项仅作历史参考，实际门禁按候选版本的用例清单核对，防止新增测试漏注册。

ASan+UBSan 与 TSan 使用不同构建目录；C/C++、Lua 静态库和原生动态模块均覆盖检测。
计划采用的基础参数分别为 `-fsanitize=address,undefined -fno-omit-frame-pointer`
和 `-fsanitize=thread -fno-omit-frame-pointer`，编译及链接参数必须一致。
实现时补充可复现构建入口，并记录编译器/标准库、flags、依赖覆盖范围及环境变量。

- ASan 开启 leak 检查，UBSan/TSan 错误直接使测试失败；原版独立构建的差分结果与重构版 sanitizer 结果分开记录。
- 并发用例用 barrier/latch 或协议握手控制交错，不靠固定 sleep 或反复重试到成功掩盖竞态。
- 每个 runner 有总超时，失败也销毁子进程并解除阻塞；不使用 detach 掩盖退出问题。
- 宿主无法运行 TSan 时记录阻塞并换支持环境；不得把跳过或运行器崩溃记为通过。
- sanitizer 缺陷修复后复跑受影响用例及完整对应门禁，保留失败证据和修复提交。

## 8C：性能基线与优化决策

比较 original 与 refactor 的同一 workload；固定 CPU/内存、系统/内核、编译优化、worker 数、
payload 分布、并发量及连接数。发布性能用 Release 无 sanitizer 构建，诊断构建数据单列。
建议每场景预热 30 秒、测量至少 120 秒、独立重复至少 5 次；短场景若不足以稳定则延长并记录原因。

| 场景 | 变化维度 | 指标 |
| --- | --- | --- |
| Actor 消息与 Lua RPC | 单/多 producer、冷热服务、64 B/1 KiB/64 KiB payload | 吞吐、p50/p95/p99、排队延迟、公平性 |
| TCP/UDP/分布式 RPC | 连接数、并发、慢读、cluster 分片阈值前后及大消息 | 有效吞吐、端到端延迟、错误率、峰值内存 |
| 服务/共享数据生命周期 | 创建销毁速率、读者数、版本更新频率 | 每服务内存、分配次数、GC/更新耗时 |
| 空闲与停机 | worker 数、空闲连接、在途消息 | 空闲 CPU、RSS/FD、停止到进程退出耗时 |

采样同时记录成功/失败/超时请求数，分位数不能丢掉超时样本而制造低延迟。
持续负载需记录实际发起速率，区分客户端受限和服务器饱和；记录完整分布及重复实验波动，不能只报最优值。

先在 8C 冻结业务 SLO 与可接受回退阈值，再评判候选版本。当前没有可支撑固定百分比的基线，
不预先承诺吞吐提升；阈值未确定时报告测量结果并标记性能验收未完成，不能事后调整标准让结果通过。
只有证据指向瓶颈时才评估调度批量、公平性、buffer pool、pmr 或 timer 结构，每项单独做前后对照与回归。

## 8D：故障与长稳

至少完成一次连续 24 小时的代表性混合负载，涵盖服务创建/退出、TCP/IPv4 UDP、跨节点 RPC、
重连、大包、业务状态恢复及共享数据更新；固定随机种子和负载参数以便复现。
每 10 秒采集 RSS、FD、线程、服务数、连接数、待处理请求/队列字节及可用的分配统计；故障事件单独打点。

故障阶段覆盖节点终止/重启、连接中断、对端慢读、目标服务退出、启动失败、日志重开和状态写入失败。
网络黑洞/远端无响应若原版没有自动超时，记录等待语义并由测试 watchdog 收尾，不能承诺透明恢复。
需要系统级故障注入时使用隔离测试环境，避免影响日常运行实例。

验收先在预跑中冻结资源上限与稳定区间。正式运行检查热身后的 RSS/FD/服务数是否持续单调增长，
将缓存保留与泄漏区分并给出依据。每次故障后的队列与资源应回到约定区间，未回收请求有明确解释。
停机后确认子进程、FD、线程和 PID/锁清理完成；进程内仍驻留的缓存由退出释放并记录统计口径。
任何崩溃、无解释的数据丢失/重复、内存错误、死锁或无法解释的持续增长均阻止通过。
影响稳定性的修复合入后重新计算完整长稳时长，不能拼接多个失败运行凑满 24 小时。

## 8E：发布材料与最终检查

发布产物包括可执行文件、必需模块、Lua 服务/库、示例配置、依赖与许可证清单，以及构建版本和校验信息。
在干净输出目录或独立环境构建/启动，验证模块路径没有依赖开发机旧 build 产物；
先执行单节点 smoke，再执行已承诺的多节点及运维场景。

文档需列出支持矩阵、配置默认值与迁移差异、启动/停止、日志与诊断、已知限制、测试命令和原始证据位置。
回滚演练保留旧二进制、配置和业务状态备份，验证状态格式兼容性；不依赖破坏性 Git 重置恢复服务。
发布检查清单完成表示候选版本具备发布条件，实际发布作为后续操作执行，本次任务只制定计划。

- [ ] 功能矩阵与候选 SHA 一致，必选项无未解释的缺口，原版/新版/混部差分通过。
- [ ] Debug/Release、ASan+UBSan、TSan 和业务回归通过，环境限制无伪通过。
- [ ] 完整 24 小时长稳通过；故障后恢复、资源回收和停机都有证据。
- [ ] 性能原始数据、波动、阈值及结论齐全；回退问题已修复或按冻结标准处理。
- [ ] 干净环境启动、配置迁移与回滚演练通过，运行指南和限制表可独立使用。

每次验收报告使用统一字段：候选 SHA、上游 SHA、环境、构建参数、命令、用例范围、
起止时间、成功/失败/跳过数量、日志/原始数据位置、缺陷及结论。未来建议按
“差分基础设施 → sanitizer 门禁 → benchmark → 长稳/故障 → 发布文档”拆分提交。
